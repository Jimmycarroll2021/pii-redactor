# Roadmap: PII Redactor Scale-Test Recovery

**Created:** 2026-05-01
**Project:** PII Redactor Scale-Test Recovery
**Granularity:** standard

## Overview

Three phases rebuild the missing scale-test evidence trail from the ground up. Phase 1 documents current evidence and artifact layout. Phase 2 creates the reproducible corpus and harness. Phase 3 runs scaled tests and produces reports that can be trusted.

| # | Phase | Goal | Requirements |
|---|-------|------|--------------|
| 1 | Scale-Test Evidence Baseline | Capture what exists, what is missing, and where future artifacts live | EVID-01, EVID-02, EVID-03 |
| 2 | Scale Harness and Synthetic Corpus | Build repeatable corpus generation plus direct/API benchmark harnesses | CORP-01..05, HARN-01..04 |
| 3 | Scaled Runs and Reporting | Execute scale runs and publish correctness, safety, and performance reports | SAFE-01..05, PERF-01..04, DOCS-01..03 |

## Phase 1: Scale-Test Evidence Baseline

**Goal:** Turn the current search results into durable project evidence and define the artifact contract.

**Requirements:** EVID-01, EVID-02, EVID-03

**Success criteria:**
1. `scale-tests/README.md` defines the directory structure and artifact naming rules.
2. `scale-tests/evidence-baseline.md` lists confirmed traces and missing historical artifacts.
3. No claim says old scale tests passed unless backed by a file path or log excerpt.
4. Latest project state points to Phase 2 as the next implementation step.

**Suggested files:**
- `scale-tests/README.md`
- `scale-tests/evidence-baseline.md`
- `.planning/STATE.md`

## Phase 2: Scale Harness and Synthetic Corpus

**Goal:** Create repeatable synthetic inputs and benchmark runners for library and HTTP batch paths.

**Requirements:** CORP-01, CORP-02, CORP-03, CORP-04, CORP-05, HARN-01, HARN-02, HARN-03, HARN-04

**Success criteria:**
1. Synthetic corpus generator can produce small, medium, and large corpora from a seed.
2. Expected labels are written separately from generated documents.
3. Direct library benchmark writes JSONL raw results and summary metrics.
4. HTTP batch benchmark targets `/redact/batch` and records concurrency settings.
5. Harness parameters are documented and stable.

**Suggested files:**
- `scale-tests/generate_corpus.py`
- `scale-tests/run_library_benchmark.py`
- `scale-tests/run_http_batch_benchmark.py`
- `scale-tests/fixtures/`
- `scale-tests/runs/`

## Phase 3: Scaled Runs and Reporting

**Goal:** Run the harness and produce trustworthy performance, correctness, and safety reports.

**Requirements:** SAFE-01, SAFE-02, SAFE-03, SAFE-04, SAFE-05, PERF-01, PERF-02, PERF-03, PERF-04, DOCS-01, DOCS-02, DOCS-03

**Success criteria:**
1. At least one direct library run is captured for 1k+ synthetic documents.
2. At least one HTTP batch run is captured with two concurrency settings.
3. Reports include docs/sec, estimated docs/day, latency percentiles, error rate, and category metrics.
4. Safety checks explicitly confirm no expected original PII appears in redacted outputs, spans, safe PII table, or logs.
5. Runbook explains exact commands to reproduce the latest benchmark.

**Suggested files:**
- `scale-tests/runs/<timestamp>/results.jsonl`
- `scale-tests/runs/<timestamp>/summary.json`
- `scale-tests/runs/<timestamp>/REPORT.md`
- `scale-tests/RUNBOOK.md`

## Dependency Notes

- Phase 2 depends on Phase 1 artifact layout.
- Phase 3 depends on Phase 2 harness and corpus outputs.
- HTTP benchmarking requires a running API service; direct library benchmarking does not.
