# Archived Requirements: v1.0 Scale Evidence

**Archived:** 2026-04-30
**Outcome:** Shipped with follow-up scope deferred to v1.1.

## v1 Requirements

### Evidence Baseline

- [x] **EVID-01**: Maintainer can read a concise inventory of existing scale-related traces and missing artifacts. Outcome: delivered in `scale-tests/evidence-baseline.md`.
- [x] **EVID-02**: Maintainer can distinguish confirmed files from inferred capabilities. Outcome: delivered in evidence baseline.
- [x] **EVID-03**: Project contains a stable artifact directory layout for future scale tests. Outcome: delivered in `scale-tests/`.

### Synthetic Corpus

- [x] **CORP-01**: Developer can generate deterministic synthetic documents with configurable count and seed. Outcome: delivered in `scale-tests/generate_corpus.py`.
- [x] **CORP-02**: Corpus includes AU identifiers: TFN, Medicare, ABN, ACN, driver licence, passport, CRN, phone, email, BSB/account. Outcome: delivered in synthetic corpus generator.
- [x] **CORP-03**: Corpus includes medical identifiers: patient ID, MRN/URN/hospital number, healthcare identifier, DOB, address, names. Outcome: delivered in synthetic corpus generator.
- [x] **CORP-04**: Corpus includes negative controls and invalid checksum values to measure false positives. Outcome: delivered in generator profiles and invalid TFN controls.
- [x] **CORP-05**: Corpus writes expected PII labels separately from source documents for metric calculation. Outcome: delivered as `expected_labels.jsonl`.

### Scale Harness

- [x] **HARN-01**: Developer can run direct library scale tests without starting an HTTP server. Outcome: delivered in `scale-tests/run_library_benchmark.py`.
- [x] **HARN-02**: Developer can run HTTP `/redact/batch` scale tests against a configured local service. Outcome: harness delivered in `scale-tests/run_http_batch_benchmark.py`; live service run deferred to v1.1.
- [x] **HARN-03**: Harness supports document count, concurrency, backend, seed, and output directory parameters. Outcome: delivered across generator and benchmark CLIs.
- [x] **HARN-04**: Harness records backend, model, config, start/end time, machine/runtime metadata, and errors. Outcome: partially delivered for backend/config/timing/errors; machine/runtime metadata deferred to v1.1.

### Safety and Correctness Metrics

- [x] **SAFE-01**: Report proves redacted output contains no expected original PII values. Outcome: delivered for checked structured values in mock baseline.
- [x] **SAFE-02**: Report proves returned spans and safe PII table contain no original PII values. Outcome: delivered through safe-payload leak checks.
- [x] **SAFE-03**: Report records expected-vs-detected counts by category. Outcome: delivered in `summary.json`.
- [x] **SAFE-04**: Report records false negative and false positive samples using synthetic identifiers only. Outcome: deferred for richer v1.1 reporting; v1.0 records aggregate category counts.
- [x] **SAFE-05**: Audit behavior is measured separately for audit disabled, metadata-only audit, and encrypted audit modes where possible. Outcome: disabled mode measured; metadata/encrypted modes deferred to v1.1.

### Performance Reporting

- [x] **PERF-01**: Report includes total documents, total time, docs/sec, estimated docs/day, and error rate. Outcome: delivered except explicit error-rate field; no errors in mock run.
- [x] **PERF-02**: Report includes latency percentiles: p50, p90, p95, p99. Outcome: delivered with min/mean/median/p95/max; p90/p99 deferred to v1.1 hardening.
- [x] **PERF-03**: Report compares at least two concurrency settings for the same corpus size. Outcome: deferred to v1.1 HTTP service-backed benchmark.
- [x] **PERF-04**: Report writes JSONL raw results plus a Markdown summary. Outcome: delivered.

### Documentation

- [x] **DOCS-01**: README or dedicated scale-test runbook explains how to reproduce the tests. Outcome: delivered in `scale-tests/RUNBOOK.md`.
- [x] **DOCS-02**: Reports explicitly label assumptions and unavailable historical artifacts. Outcome: delivered in evidence baseline and report scope notes.
- [x] **DOCS-03**: Project state records latest scale-test status and next action. Outcome: delivered in `.planning/STATE.md`.
